# How many degrees of freedom does a neutrosophic uncertainty representation have?

Code, analysis results and figure inputs for the article

> N. Tukhtamurodov, D. T. Muhamediyeva. *How Many Degrees of Freedom Does a Neutrosophic Uncertainty
> Representation Have? Theory, and Tests on Hyperspectral Convolutional Networks and Preference Data.*

The stored network outputs and trained weights (about 3 GB) are archived on Zenodo:
**DOI: 10.5281/zenodo.XXXXXXX** (placeholder until publication). Third-party data is not redistributed;
`scripts/download_data.py` fetches it from pinned sources and checks every file against its SHA-256.

## What is here

| Path | Contents |
|---|---|
| `code/` | analysis and training scripts; `common.py` holds the shared detector, bootstrap and data access |
| `code/simulation/`, `code/figures/` | Table 2 and Figs. 1–4 |
| `scripts/download_data.py` | data download and SHA-256 verification (`--checksum-only` to verify only) |
| `results/q1/` | hyperspectral tables (Tables 3–4, Section 6) and figure inputs |
| `results/preference/` | preference-detector reports (Tables 5–6, Section 7) and figure inputs |
| `results/revision/` | supplementary analyses (Tables S1–S18, Figs. S1–S5) and `REVISION_REPORT.md` |
| `results/simulation/` | Table 2 values and the S3 maps of Fig. 1 |
| `figures/` | Figs. 1–4 as generated by `code/figures/` |
| `preference_scores/` | per-pair scores (numbers only, no text) and `preference_pair_ids.csv`, which identifies every scored pair by Hugging Face revision and row index |
| `splits/` | the six 16 × 16-block train/test splits (pixel indices, labels, block IDs) |
| `plan/` | the prespecified analysis plan (`q1_plan.md`, with its SHA-256) and the CIFAR-10H plan |
| `tests/` | checks that the figure inputs reproduce the manuscript values |
| `CODE_MAP.md` | **which script produces each table, figure and number** |
| `ENVIRONMENT.md` | versions, environment variables, run times, determinism |
| `RELEASE_NOTES.md` | what was cleaned, the before/after reproduction check and the open issues |

## Quick start: regenerate the tables without a GPU

```bash
pip install -r requirements.txt            # see ENVIRONMENT.md for the PyTorch build
python scripts/download_data.py            # data/ (hyperspectral scenes, CIFAR-10H, preference pairs)
# unzip nsdof_outputs_v1.0.zip from Zenodo into outputs/

cd code
python hsi_analyze.py                      # Tables 3-4 -> results/q1
python hsi_transductive_audit.py           # Section 6.5 (read by hsi_summarize.py)
python hsi_summarize.py
python rev_engine.py && python rev_tables.py && python rev_b4_pooled.py && python rev_b4_b6steps.py
python rev_t4_tables.py                    # Table 4 † rows, Tables S1-S5
python pref_detect.py --data ../preference_scores/ns_logprob_orca_big.jsonl --out ../results/preference/rep_orca_big.json
cd ..
python code/simulation/simulation.py      # Table 2 -> results/simulation
python code/figures/make_figure_inputs.py
python code/figures/fig1_simulation.py && python code/figures/fig2_fig3_hsi.py && python code/figures/fig4_preference.py
pytest tests
```

`CODE_MAP.md` lists the entry point for every other result. Training (`hsi_run_q1.py`, `rev_run_train.py`,
`cifar10h_positive_control.py train`) and preference scoring (`pref_score.py`) need a CUDA GPU; GPU training is
not bit-reproducible, so the analyses read the archived outputs.
